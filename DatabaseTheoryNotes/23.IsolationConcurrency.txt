ISOLATION CONCURRENCY

When multiple transactions run at the same time, their operations can interfere with each other.

3 common problems arise:
	1. DIRTY READ
	2. NON-REPEATABLE READ
	3. PHANTOM READ

1. DIRTY READ
-------------
Reading data that another transaction has changed but NOT committed yet.

T1: UPDATE balance = 500
(not committed)
 
T2: SELECT balance → 500 --> "dirty" / uncommitted data.

T1: ROLLBACK

2. NON-REPEATABLE READ
----------------------

Same row gives different values when read twice within the same transaction.

T1: SELECT balance → 1000

T2: UPDATE balance = 800
COMMIT

T1: SELECT balance → 800

First read  → ₹1000
Second read → ₹800

Because T2 changed and committed the row between T1's two reads.
That's why it's called NON-REPEATABLE READ -> You cannot repeat the same read and get the same result.

3. PHANTOM READ
---------------

Same query returns different SET OF ROWS when executed twice.

T1:
SELECT * FROM Orders WHERE amount > 1000;

→ 5 rows

T2:
INSERT new order with amount = 2000
COMMIT

T1 runs the same query again:

→ 6 rows

The new row is a "phantom".
